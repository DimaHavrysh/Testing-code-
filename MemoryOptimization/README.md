# Memory Optimization

## 1. Мета роботи

Метою роботи є оптимізація Java-програми для підрахунку частоти слів у текстовому файлі, зменшення споживання оперативної пам'яті та порівняння часу виконання початкової й оптимізованої версій програми.

## 2. Опис початкової версії

У початковій версії програми використовувалися такі підходи:

- Завантаження всього тексту файлу в пам'ять за допомогою `Files.readString()`.
- Перетворення тексту на нижній регістр.
- Очищення тексту за допомогою `replaceAll()`.
- Створення масиву слів за допомогою `split()`.
- Підрахунок частоти слів за допомогою Stream API.
- Сортування всіх унікальних слів для виведення 30 найчастіших.

Такі операції можуть створювати додаткові об'єкти в пам'яті, особливо під час обробки великих текстових файлів.

## 3. Виконані оптимізації

В оптимізованій версії програми виконано такі зміни:

1. Замість завантаження всього файлу використано `BufferedReader`, який дає змогу читати файл поступово.
2. Для обробки символів використано `StringBuilder`, що дає змогу формувати одне слово за раз.
3. Для підрахунку частоти слів використано `HashMap` і метод `merge()`.
4. Для визначення 30 найчастіших слів використано `PriorityQueue`, яка зберігає лише обмежену кількість кандидатів.
5. Час виконання вимірюється за допомогою `System.nanoTime()`.
6. Збережено виведення 30 найчастіших слів у порядку спадання частоти.

## 6. Висновок

У ході лабораторної роботи було оптимізовано Java-програму для підрахунку частоти слів у текстовому файлі.

Замість завантаження всього тексту в пам'ять використано поступове читання файлу. Обробку слів виконано без створення масиву всіх слів, а для пошуку 30 найчастіших слів використано чергу з пріоритетами.

Оптимізована програма успішно обробила файл і вивела 30 найчастіших слів. Виміряний час обробки становить 38,522 мс.

Остаточну ефективність оптимізації споживання пам'яті та швидкодії необхідно підтвердити вимірюваннями початкової й оптимізованої версій за однакових умов.
