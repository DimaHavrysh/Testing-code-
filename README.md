# Triangle — рефакторинг

## Лабораторна робота

Мета роботи — виконати рефакторинг початкового класу `Triangle`, знайденого в репозиторії:

https://github.com/gprohorov/Triangle/blob/master/src/Triangle.java

Після аналізу початкового коду було знайдено такі проблеми.

## Зауваження до початкового коду

1. **Неправильне найменування getter/setter методів.** Методи `takeA()`, `takeB()`, `takeC()` та `putA()`, `putB()`, `putC()` не відповідають загальноприйнятим Java Bean naming conventions. Краще використовувати `getA()`, `getB()`, `getC()`.

2. **Неправильні назви основних методів.** Назва `perim()` скорочена і менш зрозуміла, ніж `perimeter()`. Аналогічно `equilateral()` краще назвати `isEquilateral()`, оскільки метод повертає boolean.

3. **Відсутня перевірка сторін трикутника.** Клас дозволяє створити трикутник зі стороною 0 або від'ємною стороною.

4. **Відсутня перевірка нерівності трикутника.** Можна передати такі сторони, які не можуть утворити трикутник, наприклад `1, 2, 10`.

5. **Проблема з методом `area()` для неправильних даних.** Для некоректних сторін формула Герона може повернути `NaN`, замість того щоб одразу повідомити про помилку у вхідних даних.

6. **Зайвий конструктор без параметрів.** `public Triangle() {}` створює об'єкт із нульовими сторонами, який не є коректним трикутником.

7. **Зайві setter-и.** Методи `putA()`, `putB()`, `putC()` дозволяють змінювати сторони після створення об'єкта. Через це об'єкт може перейти з коректного стану в некоректний.

8. **Поля не є `final`.** Оскільки сторони не повинні змінюватися після створення трикутника, їх доцільно зробити `final`.

9. **Метод `equilateral()` містить зайву конструкцію `if/else`.** Вираз `a == b && b == c` уже повертає boolean, тому можна безпосередньо повернути результат порівняння.

10. **Небажане пряме порівняння `double`.** У початковому коді використовується `a == b`. Для порівняння значень типу `double` доцільніше використовувати `Double.compare()`.

11. **Повторне обчислення півпериметра.** У `area()` вираз `0.5 * perim()` повторюється кілька разів. Краще один раз зберегти півпериметр у локальній змінній.

12. **Magic number `0.5`.** У формулі використовується `0.5` без пояснення. Запис `perimeter() / 2.0` робить формулу зрозумілішою.

13. **Погане форматування коду.** У початковому коді є різна кількість пробілів, наприклад `public  boolean  equilateral()`, а також різні відступи.

14. **Немає документації публічних методів.** Для зрозумілості класу можна додати JavaDoc до основних публічних методів.

15. **Метод `equals()` оголошений як `final` без необхідності.** Для цього простого класу немає потреби забороняти перевизначення `equals()` через `final`.

16. **Логіка перевірки вхідних даних відсутня в одному місці.** Перевірки сторін доцільно винести в окремий приватний метод `validateSide()`, щоб не дублювати код.

17. **Початковий клас не гарантує коректний стан об'єкта.** Після створення можна було отримати об'єкт, який фактично не є трикутником. Рефакторинг повинен забезпечити інваріант: об'єкт `Triangle` завжди має три додатні сторони, які можуть утворити трикутник.

## Виконаний рефакторинг

У результаті рефакторингу:

* змінено назви методів на зрозуміліші;
* прибрано порожній конструктор;
* прибрано setter-и;
* сторони зроблено `final`;
* додано перевірку додатності та скінченності сторін;
* додано перевірку нерівності трикутника;
* перейменовано `perim()` на `perimeter()`;
* перейменовано `equilateral()` на `isEquilateral()`;
* спрощено перевірку рівносторонності;
* використано `Double.compare()`;
* спрощено розрахунок площі за формулою Герона;
* прибрано дублювання обчислення півпериметра;
* покращено форматування та читабельність;
* винесено перевірку сторони в приватний метод `validateSide()`;
* клас зроблено незмінним (immutable) після створення.

## Висновок

Після рефакторингу клас став більш читабельним, передбачуваним і безпечним для використання. Він не дозволяє створити об'єкт із некоректними сторонами, а назви методів відповідають їх призначенню.

Основна ідея рефакторингу — не змінити призначення класу, а покращити його структуру, читабельність та надійність.
