# SorcerStone — рефакторинг

## Мета роботи

Виконати рефакторинг програми, яка читає текстовий файл, підраховує частоту слів і виводить 30 найчастіших слів.

## Зауваження до початкового коду

1. Увесь алгоритм розміщений в одному методі, тому його складно читати й тестувати.
2. Назви змінних `size`, `freq`, `distincts` і `distinctString` не всюди достатньо зрозумілі.
3. Зчитування через `Files.readAllBytes()` потребує додаткового перетворення байтів у рядок.
4. Кодування файлу явно не вказано, через що можливе неправильне читання символів.
5. Регулярний вираз `[^A-Za-z ]` залишає тільки латинські літери та пробіли, відкидаючи літери інших абеток.
6. `split(" +")` може створити порожні елементи, якщо текст починається або закінчується пробілами.
7. Перевірка `distinctString.contains(words[i])` шукає підрядок, а не окреме слово, тому може визначити слово як уже наявне помилково.
8. Операція `distinctString += ...` багаторазово створює нові рядки й неефективна для великого тексту.
9. Для пошуку унікальних слів використано ручну обробку рядка замість колекції, призначеної для зберігання частот.
10. Частота кожного слова рахується окремим проходом по всьому масиву слів, що збільшує час виконання.
11. Масив `freq` дублює дані, які логічно пов'язані зі словами, але зберігаються окремо.
12. Частота додається до назви слова у вигляді рядка, змішуючи дані та їх форматування.
13. Для сортування частоти витягуються з рядка регулярним виразом, що є складним і ненадійним способом.
14. Цикл виведення завжди очікує щонайменше 30 елементів, тому на короткому тексті може виникнути `ArrayIndexOutOfBoundsException`.
15. Змінна `size` обчислюється, але не використовується.
16. Для вимірювання часу використовується `LocalDateTime`, хоча `System.nanoTime()` краще підходить для вимірювання тривалості операції.
17. Не обробляється помилка читання файлу, наприклад, якщо файл відсутній або шлях неправильний.
18. У програмі немає окремих методів для читання файлу, підрахунку частот і виведення результатів.
19. Кількість слів для виведення зафіксована в циклі, а не задана окремою константою.
20. Порядок слів із однаковою частотою не визначений явно, тому результат може бути менш передбачуваним.

## Що зроблено під час рефакторингу

- Створено окремі методи `readText`, `countWords` і `printMostFrequentWords`.
- Використано зрозумілі назви змінних і констант.
- Для читання тексту використовується `Files.readString` із кодуванням UTF-8.
- Регулярний вираз `\p{L}` враховує літери різних абеток, а `\p{M}` — комбіновані діакритичні знаки.
- Для підрахунку частот використано `Map<String, Long>` та `Collectors.groupingBy`.
- Порожній текст обробляється без помилки.
- Слова сортуються за частотою від більшої до меншої; за однакової частоти — за алфавітом.
- Метод `limit` дозволяє безпечно вивести не більше 30 слів, навіть якщо у тексті їх менше.
- Час виконання вимірюється через `System.nanoTime()`.
- Додано обробку `IOException`.

## Структура проєкту

```text
SorcerStone-Refactored/
├── README.md
└── src/
    ├── Main.java
    └── txt/
        └── harry.txt
```

## Як запустити

1. Помістіть наданий файл `harry.txt` у папку `src/txt/`.
2. Відкрийте термінал у кореневій папці проєкту.
3. Переконайтеся, що встановлено JDK, і виконайте:

```bash
javac -encoding UTF-8 -d out src/Main.java
java -cp out Main
```

## Висновок

Після рефакторингу програма має зрозумілішу структуру, менше дублювання, надійнішу обробку тексту та помилок. Підрахунок частот виконується за допомогою колекцій Java, а виведення результатів не залежить від того, чи містить файл щонайменше 30 різних слів.
